# Лабораторная работа №1 — Менеджер задач (серверный рендеринг)

Веб-приложение «список задач» на **Node.js + Express + EJS**. Вся разметка формируется
на сервере, браузер получает готовый HTML, а данные уходят на сервер обычными HTML-формами
(`<form method="post">`) — без AJAX и без клиентского JavaScript-фреймворка.

## Возможности

* создание задачи: название, описание, статус, ожидаемая дата завершения;
* три статуса — «К выполнению», «В работе», «Выполнено»;
* фильтрация по статусу (вкладки со счётчиками), поиск по тексту, сортировка (срок / дата создания / название);
* быстрая смена статуса прямо из списка;
* редактирование и удаление задачи;
* прикрепление файлов к задаче (при создании и при редактировании), скачивание и удаление вложений;
* подсветка просроченных задач и задач со сроком «сегодня»;
* серверная валидация форм с выводом ошибок и сохранением введённых данных.

## Запуск

```bash
npm install
npm start        # http://localhost:3000
npm run dev      # то же самое с авто-перезапуском (node --watch)
PORT=4000 npm start   # другой порт
```

Node.js 18+ (проверено на Node 24).

## Маршруты

| Метод | Путь | Назначение |
|-------|------|------------|
| GET  | `/` | редирект на `/tasks` |
| GET  | `/tasks?status=&q=&sort=` | список задач с фильтрацией, поиском и сортировкой |
| POST | `/tasks` | создание задачи (multipart, вместе с файлами) |
| GET  | `/tasks/:id/edit` | форма редактирования |
| POST | `/tasks/:id` | сохранение изменений + добавление файлов |
| POST | `/tasks/:id/status` | быстрая смена статуса из списка |
| POST | `/tasks/:id/delete` | удаление задачи вместе с вложениями |
| GET  | `/tasks/:taskId/attachments/:attachmentId` | скачивание вложения |
| POST | `/tasks/:taskId/attachments/:attachmentId/delete` | удаление вложения |

Формы используют только `GET` и `POST` — HTML других методов не поддерживает.
После успешного `POST` сервер отвечает редиректом (паттерн **POST/Redirect/GET**), поэтому
обновление страницы не отправляет форму повторно. Текущие параметры фильтра переносятся в
`action` формы и в адрес редиректа, так что после действия пользователь остаётся в той же выборке.

## Хранение данных

* Задачи — `data/tasks.json`. Запись идёт во временный файл и затем `rename`, поэтому файл
  не может остаться «наполовину записанным». Все операции выстроены в очередь,
  чтобы параллельные запросы не затирали друг друга.
* Файлы — каталог `uploads/`. На диск они кладутся под сгенерированным UUID-именем
  (исходное имя пользователя на файловую систему не попадает — защита от path traversal),
  а оригинальное имя хранится в JSON и подставляется при скачивании.
* Лимиты загрузки: до 5 файлов за отправку, до 10 МБ на файл (`src/config.js`).
